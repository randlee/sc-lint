# m-4: port010-site-allow

## Description

### Goal
#786 S8 and the other shapes beyond S3/S6: PORT-010 must be allowable at a single site. An item carrying #[sc_lint(allow(PORT-010), reason = "...")] is not reported by PORT-010 (ADR-022 decision 4). This is the exception path for deliberate POSIX-only public helpers such as current_uid and is_owned_by_uid.
### Deliverables
1. Directive grammar (design): add Directive::SiteAllow { rules, reason }, separate from Allow. Rule ids are unquoted tokens (PORT-010); reason = "..." is required and non-empty. boundary.* directives parse exactly as before (frozen corpus test unchanged); boundary ignores SiteAllow and portability ignores boundary.* directives.
2. Portability honours it: PORT-010 does not report an item carrying #[sc_lint(...)] or #[sc_lint_attributes::sc_lint(...)] with allow(PORT-010). The allowance covers only that item; an allow on an impl block does not cascade to its methods, and nothing covers a module's contents, a file or a sibling.
3. Errors: malformed site allows and unknown PORT rule ids are typed errors with file and line; ids owned by other analyzers are ignored by portability.
4. Report (REQ-PRODUCT-002DA; ADR-011): FindingsReport gains an optional allowed array for allowances that suppressed a finding. Existing no-allowance reports keep schema_version 0.1.0 and omit allowed. Reports containing allowed use schema_version 0.2.0 and the new analyzer-report-v2.schema.json, which explicitly declares allowed optional and keeps additionalProperties:false. Preserve analyzer-report-v1.schema.json as the old closed contract and own both schema artifacts and fixtures. The validator dispatches by version and accepts old fixtures plus new valid allowed entries; unknown fields/malformed entries still fail. A version bump is required because an old strict v1 validator rejects this new property; it is not claimed wire-compatible with old validators. Upgrade consumers before using the new report form.
5. Tests: port010_site_allow (annotated pub #[cfg(unix)] fn current_uid not reported, unannotated sibling reported, one allowed entry), site_allow_grammar_corpus (every accepted and rejected form in the design table), site_allow_unknown_rule, site_allow_no_cascade. Fold analyzer isolation and omission-when-empty assertions into the frozen directive corpus and existing json_contract tests. Include stacked cfg/doc/inline attributes, an inherent impl method and a public function in port010_site_allow.
6. Keep sc-lint-attributes a no-op for behavior and public API; it builds on stable Linux, macOS and Windows through the existing CI matrix. Document adoption in docs-bundle/packages/sc-lint-portability.md: add the sc-lint-attributes dependency and list it in each consumer crate's boundary allowed_dependencies so SCB-DEPENDENCY stays clean. Every allowance reason names the item's actual cause.
7. Update docs/architecture.md Backend Crate Isolation and docs/sc-lint-portability/** for the portability -> directives edge under ADR-022 decision 4 and ADR-013; add the PORT-010 allowance traceability entry to docs/sc-lint-directives/requirements.md. Existing forbidden_edges against sc-lint-attributes stay unchanged; only the declared allowed_dependencies gains sc-lint-directives.
### Does Not Close
No repository-wide switch or path exclusion. Extending allow to other analyzers is later ADR-022 work.
### Active Trace
ANC-010, ANC-009. ADR-022 decision 4; ADR-010 amendment 2026-10-30 (per-site allowance).
